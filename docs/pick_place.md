# 抓取 / 放置数据集后处理

从仓库根目录运行 `split_pick_place.py`。工具读取 `dataset/raw_data`，默认把缓存、标注、报告和训练数据写到 `dataset/pick_place`，不修改原始 MCAP。

## 1. 准备环境

使用现有 ROS 2 Jazzy 工作空间与 NumPy 1 环境。复核窗口还需要系统的 `python3-pyqt5` 和 `python3-matplotlib`；LeRobot 使用独立 Python 环境。

```bash
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/local_setup.bash
```

无需启动采集节点或连接硬件。H.264 录制还需要工作空间已有的 `ffmpeg_image_transport_msgs` 和 PyAV。

## 2. 批量分析

```bash
ros2_ws/.venv-numpy1/bin/python split_pick_place.py analyze --jobs 4
```

可以使用 `--input`、`--output` 改变目录。输出与输入必须互不包含。分析中断后重新运行同一命令即可继续；已完成且源数据、处理参数未变的同步缓存会复用。`--force` 重新分析缓存，但保留未变化录制的人工标注。

自动切分规则：

1. 沿用现有夹爪平滑与稳定平台检测，寻找一次完整的开→闭→开。
2. 取第一次合拢与随后第一次打开的**时间中点**，对齐最近的有效同步图像帧；等距取较早帧。
3. `pick` 从原 episode 首帧至交界帧；`place` 从同一交界帧至原 episode 末帧。仅共享交界一帧。

多周期、缺少事件或开合不清晰时，候选列入待核对。同步失败、标定不匹配等硬错误不会被人工确认绕过。自动通过表示可按规则切分，不证明物体实际抓取或放置成功。该规则不再寻找高度峰值，也不保证交界恰好发生在抓后抬升完成时。

工具沿用转换器默认外参、采集处理快照和设备绑定检查。需要另选配置时，使用 `--config`、`--tracker-camera-extrinsic`、`--umi-tcp-extrinsic`、`--tracker-serial`、`--urdf`、`--source-camera-fps`。处理配置变化也会使旧标注失效。

## 3. 复核待核对记录

```bash
ros2_ws/.venv-numpy1/bin/python split_pick_place.py review
```

- 列表默认仅显示待核对记录；勾选“显示全部记录”可检查自动通过的结果。
- 播放、暂停或逐帧移动，对照夹爪曲线确认合拢、打开及两阶段边界。
- 可拖动曲线上的标线，或定位视频后点击“设为当前帧”。帧号从 0 开始，事件时间显示为相对首帧的秒数。
- 修改合拢/打开事件后，保存时默认重算时间中点；也可点击重算按钮预览。显式调整交界帧会作为人工覆盖保存。
- 分别将 `pick`、`place` 设为“确认保留”“排除”或“待核对”，填写备注，点击“应用并保存当前记录”。调整边界会撤销旧的通过状态，需要重新确认。
- 保存后左侧文字立即同步。保存本身不会自动确认：如果下拉框仍是“待核对”，保存结果也仍是待核对。
- 点击“删除当前记录”会立即保存，将该录制的 `pick`、`place` 两阶段都排除，并从待核对列表隐藏、切换到下一条。原始录制和缓存不会删除；勾选“显示全部记录（含已删除，可恢复）”，选中“已删除”项，再点击“恢复当前记录”即可恢复删除前最后保存的标注。删除操作不保留尚未保存的界面修改。
- 删除或恢复不会改动已经导出的数据集；完成复核后用 `export --overwrite` 更新训练数据。
- 支持只保留合格的抓取阶段；例如未释放的演示可以人工确定交界、确认抓取并排除放置。二值模式下抓取仍需要明确的合拢事件。

窗口关闭后标注仍保留。缺少可导出同步轨迹的记录可预览原始视频并排除，但不能凭视频确认跳过数据完整性检查。同一输出目录同时只允许一个分析、复核或导出进程。

## 4. 导出两套 LeRobot 数据集

关闭复核窗口后运行：

```bash
ros2_ws/.venv-numpy1/bin/python split_pick_place.py export
```

默认夹爪为二值，开=1、闭=0。保留原始连续开度时：

```bash
ros2_ws/.venv-numpy1/bin/python split_pick_place.py export --gripper-mode continuous
```

LeRobot Python 沿用现有解析顺序：`--lerobot-python`、`FASTUMI_LEROBOT_PYTHON`、用户主目录下的 `work/lerobot/.venv/bin/python`。

- 输出为 `lerobot/pick` 与 `lerobot/place`，数据集标识分别为 `fastumi/pick`、`fastumi/place`，任务描述分别为 `pick`、`place`。
- 每段首帧 TCP 坐标系归零；位置单位米，姿态为旋转向量（弧度），state/action 均为同一图像时刻的示教轨迹，保持现有 7 维 LeRobot 契约。
- 输出固定 30 Hz、224×224 图像，每段至少 16 帧。最多补齐连续 2 个缺失帧；更长缺口拒绝对应阶段，不额外切成新 episode。
- 连续夹爪来自 `raw_openness` 的同步结果，短缺口按线性插值；二值夹爪按已确认事件生成，补帧采用最近邻。
- 未确认阶段不导出，两套数据集数量可以不同。某阶段没有合格数据时，不创建空 LeRobot 数据集，原因写入导出报告。
- 导出先写临时目录并用现有 LeRobot 写入器回读校验，全部成功后整体发布。已有输出默认拒绝覆盖；重导出时显式加 `--overwrite`。失败时保留诊断目录及原数据集。
- 导出前再次检查源内容指纹。源变化后先重新分析，再复核失效标注。

## 输出文件

| 路径（相对输出目录） | 用途 |
| --- | --- |
| `segments.json` | 源相对路径、SHA-256、纳秒时间轴、帧索引、事件、切点与人工标注 |
| `report.json` | 全部记录的阶段状态、检测及同步异常 |
| `export_report.json` | 两套数据集数量、未导出记录与原因 |
| `lerobot/*/meta/fastumi.json` | 每个训练 episode 的源录制、原帧范围、补帧映射与标注溯源 |
| `.cache/` | 同步 HDF5、夹爪曲线及按需生成的视频预览 |

缓存与录制内容指纹绑定。正常使用请保留缓存，删除后需要重新分析。本工具不做物体类别识别、训练/验证划分或机器人侧策略切换；以后划分训练集时，应按原始录制分组，避免同源片段跨集合。
